# 汽車展示網頁教學計畫（BMW 網站觀察案例）

## 目標與定位

以 BMW 台灣網站的「車型探索」資訊架構作為觀察對象，讓學生用 **HTML5、Bootstrap 5.3 與少量原生 JavaScript** 製作一頁原創的汽車展示網站。成果是課堂練習，**非 BMW 官方網站**；展示車款、圖片與表單皆用教學示意內容，不蒐集真實個資。

## 網站觀察與設計依據

BMW 台灣車型總覽可依車身類型、系列、動力選擇瀏覽；車型項目提供進一步探索、訂製或預約賞車等入口。教學版保留「分類→比較→行動」的資訊流程，改寫成原創內容與簡化互動，不複製官網視覺、文案、照片或 Logo。

- 官方觀察：[BMW 台灣車型總覽](https://www.bmw.com.tw/zh/all-models.html)
- 技術參考：[Bootstrap 入門](https://getbootstrap.com/docs/5.3/getting-started/introduction/)、[格線](https://getbootstrap.com/docs/5.3/layout/grid/)、[導覽列](https://getbootstrap.com/docs/5.3/components/navbar/)、[卡片](https://getbootstrap.com/docs/5.3/components/card/)、[無障礙](https://getbootstrap.com/docs/5.3/getting-started/accessibility/)

## 頁面模型

1. 語意化導覽：品牌研究說明、車款、設計重點、聯絡示範。
2. 靜態主視覺：一句核心訊息與清楚的行動按鈕。初版不用輪播。
3. 車型區：三張**虛構**車型卡，示範動力分類與響應式格線；數據不宣稱對應真車。
4. 設計重點：說明資訊呈現、RWD 和可近用的設計選擇。
5. 示範表單：有 label、required 和前端驗證；送出僅顯示提示，不傳送或儲存資料。
6. 頁尾：註明非官方課堂作品、資料來源與素材來源。

## 實作方法與課程順序

| 階段 | 學生任務 | 核心技術 | 交付與檢查 |
|---|---|---|---|
| 1. 觀察與結構 | 記錄官網的分類、卡片、行動入口；畫低保真線框圖；寫原創文案 | `header`、`nav`、`main`、`section`、`footer`、標題階層 | 來源紀錄、線框圖、語意 HTML |
| 2. 視覺與排版 | 完成導覽、靜態主視覺、三張卡片及表單 | Bootstrap `container`、`row`、`col`、navbar、card、button、form | 手機優先的單頁原型 |
| 3. 驗證與改版 | 檢查鍵盤導覽、標籤、對比與三種畫面寬度；根據發現修改 | CSS 變數、媒體查詢、表單驗證 | 修正紀錄與截圖 |

進階作業可加入原生 JavaScript 車型篩選，必須含「全部」與「無結果」狀態。初階版的分類應做成明確的靜態標籤或頁內錨點，避免假裝可篩選。

## 兩位代理的交叉檢視與修訂

- 網頁設計檢視：建議把「設計觀察與再創作」列為第一階段正式交付；限縮初階元件；以 375、768、1440 px 檢查版面。
- 教學方法檢視：同意單頁架構與靜態主視覺；建議先做靜態分類，進階再加篩選；卡片採虛構資料，表單不儲存個資。
- 綜合修訂：採三階段、靜態 Hero、三張虛構車款卡、無資料儲存的示範表單；把互動篩選列為進階。此決策讓學生先掌握結構和 RWD，再處理 JavaScript。

## 驗收與評量

- 語意 HTML 與資訊架構：20%。標題順序正確、區塊語意清楚。
- 響應式排版：25%。檢查 375、768、1440 px，無橫向溢出，卡片可讀。
- Bootstrap 元件與操作：20%。導覽、卡片、按鈕、表單可正常使用。
- 可近用性：20%。鍵盤可操作、圖片有適當替代文字、表單有可見標籤、文字對比足夠。
- 原創與文件：15%。標示教學用途、記錄來源與修訂原因，使用有授權或自製素材。
